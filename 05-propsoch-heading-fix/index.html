2 h1 tags found

Two h1 elements on one page (mobile + desktop hero variants both render) — screen readers announce two competing page titles.
Hidden sr-only text reads "Sales Pitch?" while sighted users see rotating words — mismatch for assistive tech.
Search engines split ranking signals across two H1s instead of one clear page topic.
<h1>…a broker's Sales Pitch?</h1> <h1>…a broker's Fake Claims?</h1>

a broker's Sales Pitch?

Rotating word: sales pitch, fake claims, or half info.

1 h1 tag — semantic

Exactly one h1 — one page, one title, one ranking signal.
Rotating words live in an aria-live region: screen readers hear each change, matching the visual.
Responsive type scales with CSS — no duplicate markup for mobile/desktop.
<h1>…<span aria-live="polite">…</span></h1>

What changed (3 small edits)

  • Merged two H1s into one — removed the duplicate desktop/mobile hero markup; one responsive heading now serves all screens.
  • Accessible rotator — rotating words moved into an aria-live="polite" region so screen readers announce them.
  • Removed the sr-only mismatch — assistive text now describes the animation instead of contradicting it.
